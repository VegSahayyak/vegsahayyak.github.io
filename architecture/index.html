Native Security & Binary Hardening (libveg_vault.so) ​

In v2.2.1, critical signal processing algorithms and licensing verification are encapsulated within a compiled Native C++ Library (libveg_vault.so). This provides defense-in-depth protection for commercial enterprise integrations:

  • Anti-Tamper & Anti-Reversing: Core telematics logic is protected against Dalvik/ART bytecode decompilation, dynamic hooking, and runtime memory tampering.
  • Offline Cryptographic Integrity: High-assurance license validation runs locally on-device, verifying cryptographic signatures without exposing raw mathematical constants or logic to the Java/Kotlin runtime layer.
  • Minimal Binary Footprint: Fully stripped to less than 300KB per ABI, preserving the SDK's lightweight footprint with zero impact on host application APK size.

Enterprise Licensing Model ​

The SDK operates exclusively on an offline-first Commercial Enterprise License model, eliminating runtime third-party authentication servers or tracking dependencies:

  1. Self-Contained Claims: Your commercial license key is a signed JSON Web Token (JWT) that encodes authorized module entitlements (such as :speed-ui, :speed-overlay, :speed-autostart) and expiration bounds.
  2. 100% Offline Execution: All license verification runs locally on-device within the native vault. Fleets and logistics vehicles operate uninterrupted in remote, tunnel, or off-grid environments without periodic server ping requirements.

Signal Processing & Telematics Engine ​

GPS hardware sensors on mobile devices frequently produce velocity noise spikes, multipath signal reflections, and intermittent signal drift (especially in urban canyons or under bridges). The TelematicsEngine in speed-core applies a multi-stage mathematical pipeline before emitting speed updates.

Live TelematicsEngine Mathematics Pipeline
EMA Factor (α): 0.30
SmoothedVelocity[t] = 0.30 · Raw[t] + 0.70 · Smoothed[t-1]Trigger: > Upper Limit | Dismiss: < Lower Hysteresis Bound
TimestampRaw GPS (Jitter)EMA SmoothedHysteresis State

1. Accuracy Confidence Gating ​

Raw GPS fixes with an estimated horizontal accuracy greater than our proprietary internal threshold (or missing speed precision) are discarded:

Gating Rule

text
Accept GPS Fix IF: horizontalAccuracy <= CONFIDENCE_THRESHOLD (2σ confidence)

When a reading is rejected, the engine emits SpeedData.LowAccuracy, preventing erratic spikes while preserving the last valid smoothed speed.

2. Exponential Moving Average (EMA) ​

To eliminate abrupt needle shaking while retaining immediate responsiveness to actual vehicle acceleration, the engine applies an Exponential Moving Average using proprietary coefficients gated inside libveg_vault.so.

Mathematical Smoothing Formula

text
SmoothedVelocity[t] = α · RawVelocity[t] + (1 - α) · SmoothedVelocity[t - 1]
  • S_t: Smoothed speed at timestamp t (in meters/second).
  • Y_t: Raw velocity reading from the GPS provider.
  • S_{t-1}: Previous smoothed speed state.
  • α: Calibrated weighting coefficient (executed securely inside libveg_vault.so).

3. Dual Schmitt Trigger Hysteresis (Max & Min Limits) ​

A major problem with standard telematics alerting is alarm flutter (e.g. at 80.1 km/h the alarm fires, at 79.9 km/h it shuts off, causing rapid flickering and annoying audio chatter).

The SDK's TelematicsEngine implements a Dual Schmitt Trigger Hysteresis state machine covering both Maximum Speed Limits and Minimum Speed Corridors. These dynamic limits are no longer set manually; they are now automatically fed by the selected DrivingProfile (e.g. CarHighway, EScooter):

A. Maximum Speed Ceiling Hysteresis ​

  • Trigger Threshold: Warning activates when speed exceeds the upper bound limit.
  • Dismissal Threshold: Warning deactivates when speed drops below the required hysteresis baseline.
  • Result: Sets isOverLimit = true in SpeedData.SpeedChanged.

B. Minimum Speed Corridor Hysteresis ​

  • Startup Safety Guard (hasReachedSafeSpeed): Prevents false under-speed alarms when the vehicle is stationary or starting from a parking stop until it first accelerates past a safe baseline.
  • Trigger Threshold: Warning activates when driving speed drops below the corridor floor.
  • Dismissal Threshold: Warning deactivates once speed recovers safely into the corridor.
  • Result: Sets isUnderLimit = true in SpeedData.SpeedChanged.

  1. AutoStartManager (:speed-autostart): This is the new recommended strategy for battery optimization. By utilizing Google Play Services IN_VEHICLE transitions, it detects when a trip starts or stops using the low-power sensor hub, bypassing OEM background killers without relying on continuous GPS polling.
  2. ScreenStateWatcher: Dynamically observes display state. If the host application configures updateWhileScreenOff = false, the GPS hardware is immediately turned off when the screen sleeps, reducing power consumption by up to 68%.
  3. Dynamic Status Bar Icons: Speed is rendered directly into the system status bar as a vector numeric drawable, allowing drivers to monitor speed without keeping the screen active.
